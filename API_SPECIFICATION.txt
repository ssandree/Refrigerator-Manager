# API 명세서 (Refrigerator Manager API)

## 인증 (Authentication)
**Base Path:** `/auth`

### 회원가입
- **POST** `/auth/register`
- **설명:** 새 사용자 등록
- **인증:** 불필요
- **요청:**
```json
{
  "name": "홍길동",
  "email": "user@example.com",
  "password": "password123"
}
```
- **응답:**
```json
{
  "success": true,
  "message": "User registered successfully",
  "data": {
    "user": {
      "id": "uuid-string",
      "name": "홍길동",
      "email": "user@example.com",
      "age": null,
      "sex": null,
      "weight": null,
      "activityLevel": null,
      "bmi": null
    },
    "token": "jwt-token-string"
  }
}
```
- **에러:** 400 (이미 존재하는 이메일 등)

### 로그인
- **POST** `/auth/login`
- **설명:** 사용자 로그인
- **인증:** 불필요
- **요청:**
```json
{
  "email": "user@example.com",
  "password": "password123"
}
```
- **응답:**
```json
{
  "success": true,
  "message": "Login successful",
  "data": {
    "user": {
      "id": "uuid-string",
      "name": "홍길동",
      "email": "user@example.com",
      "age": 30,
      "sex": "male",
      "weight": 70.5,
      "activityLevel": "moderate",
      "bmi": 22.5
    },
    "token": "jwt-token-string"
  }
}
```
- **에러:** 400 (잘못된 이메일/비밀번호)

### 토큰 갱신
- **POST** `/auth/refresh`
- **설명:** 만료된 토큰 갱신
- **인증:** 불필요 (만료된 토큰 허용)
- **요청:**
```json
{
  "token": "expired-jwt-token-string"
}
```
- **응답:**
```json
{
  "success": true,
  "message": "Token refreshed successfully",
  "data": {
    "user": {
      "id": "uuid-string",
      "name": "홍길동",
      "email": "user@example.com",
      "age": 30,
      "sex": "male",
      "weight": 70.5,
      "activityLevel": "moderate",
      "bmi": 22.5
    },
    "token": "new-jwt-token-string"
  }
}
```
- **에러:** 401 (유효하지 않은 토큰)

### 현재 사용자 정보 조회
- **GET** `/auth/me`
- **설명:** 현재 로그인한 사용자 정보 조회
- **인증:** 필요 (Bearer Token)
- **응답:**
```json
{
  "id": "uuid-string",
  "name": "홍길동",
  "email": "user@example.com",
  "age": 30,
  "sex": "male",
  "weight": 70.5,
  "activityLevel": "moderate",
  "bmi": 22.5
}
```
- **에러:** 404 (사용자 없음)

### 사용자 정보 수정
- **PUT** `/auth/user/{userId}`
- **설명:** 사용자 정보 수정 (본인만 수정 가능)
- **인증:** 필요 (Bearer Token)
- **요청:**
```json
{
  "name": "홍길동",
  "age": 31,
  "sex": "male",
  "weight": 72.0,
  "activityLevel": "high",
  "bmi": 23.0
}
```
- **응답:**
```json
{
  "id": "uuid-string",
  "name": "홍길동",
  "email": "user@example.com",
  "age": 31,
  "sex": "male",
  "weight": 72.0,
  "activityLevel": "high",
  "bmi": 23.0
}
```
- **에러:** 403 (본인이 아님), 404 (사용자 없음)

### 계정 삭제
- **DELETE** `/auth/user/{userId}`
- **설명:** 계정 삭제 (본인만 삭제 가능, 관련 데이터도 함께 삭제)
- **인증:** 필요 (Bearer Token)
- **응답:** `{"success": true, "message": "계정이 성공적으로 삭제되었습니다"}`
- **에러:** 403 (본인이 아님), 404 (사용자 없음)

## 음식 관리 (Foods)
**Base Path:** `/foods`
**인증:** 모든 엔드포인트에 Bearer Token 필요

### 음식 생성
- **POST** `/foods`
- **설명:** 새 음식 등록
- **요청:**
```json
{
  "imageUrl": "https://example.com/image.jpg",
  "category": "채소",
  "name": "양파",
  "quantity": 3,
  "weight": "500g",
  "purchaseDate": "2024-01-15",
  "expiryDate": "2024-01-25",
  "storageLocation": "냉장실",
  "alertBeforeDays": 3
}
```
- **응답:**
```json
{
  "success": true,
  "message": null,
  "data": {
    "id": "uuid-string",
    "imageUrl": "https://example.com/image.jpg",
    "category": "채소",
    "name": "양파",
    "quantity": 3,
    "weight": "500g",
    "registeredAt": "2024-01-15T10:30:00",
    "purchaseDate": "2024-01-15",
    "expiryDate": "2024-01-25",
    "storageLocation": "냉장실",
    "alertBeforeDays": 3
  }
}
```
- **특징:** 
  - purchaseDate 기본값 설정 (FE에서 필드 누락 시 자동 today 적용)
  - userId 자동 설정 (get_current_user로)

### 음식 목록 조회 (필터링)
- **GET** `/foods`
- **설명:** 음식 목록 조회 (다양한 필터 지원)
- **Query Parameters:**
  - `category` (optional): 카테고리 필터
  - `location` (optional): 보관 장소 필터
  - `expired` (optional, bool): 만료 여부 (true/false)
  - `expiring` (optional, bool): 임박 여부
  - `sort` (optional): 정렬 (예: "expiryDate ASC")
- **응답:**
```json
{
  "success": true,
  "message": null,
  "data": [
    {
      "id": "uuid-string-1",
      "imageUrl": "https://example.com/image1.jpg",
      "category": "채소",
      "name": "양파",
      "quantity": 3,
      "weight": "500g",
      "registeredAt": "2024-01-15T10:30:00",
      "purchaseDate": "2024-01-15",
      "expiryDate": "2024-01-25",
      "storageLocation": "냉장실",
      "alertBeforeDays": 3
    },
    {
      "id": "uuid-string-2",
      "imageUrl": null,
      "category": "육류",
      "name": "닭가슴살",
      "quantity": 2,
      "weight": "300g",
      "registeredAt": "2024-01-16T14:20:00",
      "purchaseDate": "2024-01-16",
      "expiryDate": "2024-01-20",
      "storageLocation": "냉동실",
      "alertBeforeDays": 2
    }
  ]
}
```
- **특징:**
  - Filter chaining 정확함
  - expired / expiring 구분 매우 정확
  - SQL Filter → Python Filter → 정렬 처리 순서 잘 잡힘
  - sort nulls_last까지 들어간 점 매우 세심함
  - userId로 자동 필터링 (본인 음식만 조회)

### 음식 수정
- **PUT** `/foods/{foodId}`
- **설명:** 음식 정보 수정
- **요청:**
```json
{
  "quantity": 5,
  "expiryDate": "2024-01-30",
  "storageLocation": "냉동실"
}
```
- **응답:**
```json
{
  "success": true,
  "message": null,
  "data": {
    "id": "uuid-string",
    "imageUrl": "https://example.com/image.jpg",
    "category": "채소",
    "name": "양파",
    "quantity": 5,
    "weight": "500g",
    "registeredAt": "2024-01-15T10:30:00",
    "purchaseDate": "2024-01-15",
    "expiryDate": "2024-01-30",
    "storageLocation": "냉동실",
    "alertBeforeDays": 3
  }
}
```
- **에러:** 404 (FOOD_NOT_FOUND)
- **특징:** Optional 필드만 업데이트하는 방식 정확함

### 음식 단일 삭제
- **DELETE** `/foods/{foodId}`
- **설명:** 음식 삭제
- **응답:**
```json
{
  "success": true,
  "message": "음식이 삭제되었습니다"
}
```
- **에러:** 404 (FOOD_NOT_FOUND)
- **특징:** 유저 validation 포함한 점 굿

### 음식 일괄 삭제
- **DELETE** `/foods`
- **설명:** 여러 음식 일괄 삭제
- **요청:**
```json
{
  "foodIds": ["uuid-string-1", "uuid-string-2", "uuid-string-3"]
}
```
- **응답:**
```json
{
  "success": true,
  "message": "3개의 음식이 삭제되었습니다",
  "deletedCount": 3
}
```
- **에러:** 400 (삭제할 음식 ID가 필요)
- **특징:**
  - 유저 id 기반 제한 → 다른 사람 음식 삭제 불가
  - 보안적으로 정답

## 식사 기록 (Meals)
**Base Path:** `/meals`
**인증:** 모든 엔드포인트에 Bearer Token 필요

### 식사 목록 조회
- **GET** `/meals`
- **설명:** 식사 기록 조회 (다양한 필터 지원)
- **Query Parameters:**
  - `date` (optional): 특정 날짜 (YYYY-MM-DD)
  - `startDate` (optional): 조회 기간 시작일
  - `endDate` (optional): 조회 기간 종료일
  - `mealType` (optional, alias: "type"): 식사 타입 (breakfast, lunch, dinner, snack)
  - `recipeId` (optional): 레시피 ID
- **응답:**
```json
{
  "success": true,
  "message": null,
  "data": [
    {
      "id": "uuid-string",
      "recipeId": "recipe-uuid",
      "foodIds": ["food-uuid-1", "food-uuid-2"],
      "quantity": "1인분",
      "consumedAt": "2024-01-15T12:30:00",
      "registeredAt": "2024-01-15T12:00:00",
      "notes": "맛있었음",
      "mealType": "lunch"
    }
  ]
}
```
- **에러:** 400 (Invalid mealType)
- **특징:** 
  - recipeId가 있으면 validate_recipe_exists()로 존재 확인
  - userId로 자동 필터링

### 식사 상세 조회
- **GET** `/meals/{mealId}`
- **설명:** 특정 식사 기록 상세 조회

## 즐겨찾기 레시피 (Favorite Recipes)
**Base Path:** `/favorite-recipes`
**인증:** 모든 엔드포인트에 Bearer Token 필요

### 즐겨찾기 목록 조회
- **GET** `/favorite-recipes`
- **설명:** 유저의 즐겨찾기 레시피 목록 조회
- **응답:**
```json
{
  "success": true,
  "message": null,
  "data": [
    {
      "id": "uuid-string",
      "recipeName": "김치볶음밥",
      "calories": 450,
      "healthGoal": 1,
      "imageUrl": "https://example.com/recipe1.jpg",
      "requiredfoods": ["김치", "밥", "양파"],
      "carbohydrates": 60.5,
      "protein": 15.2,
      "fat": 12.3,
      "sodium": 1200.0,
      "vitamin_c": 25.0,
      "vitamin_d": null,
      "zinc": 2.5
    }
  ]
}
```
- **특징:**
  - get_current_user()로 userId 자동 가져옴
  - FavoriteRecipe 테이블에서 userId로 필터
  - Recipe JOIN해서 FE에게 바로 쓸 수 있는 recipe list 반환

### 즐겨찾기 확인
- **GET** `/favorite-recipes/{recipeId}/check`
- **설명:** 특정 recipe가 즐겨찾기인지 확인
- **응답:**
```json
{
  "success": true,
  "message": null,
  "data": {
    "isFavorite": true
  }
}
```
- **특징:**
  - validate_recipe_exists()로 존재 확인
  - is_favorite() 실행
  - boolean 반환

### 즐겨찾기 추가
- **POST** `/favorite-recipes/{recipeId}`
- **설명:** 즐겨찾기 추가
- **응답:**
```json
{
```

**인증:** 모든 엔드포인트에 Bearer Token 필요

- **설명:** 식사 관련 통계 조회
- **응답:**
```json

  "data": {

    },

    "totalCalories": 13500
  }

```
- **특징:** userId로 자동 필터링

### 일일 건강 통계
- **GET** `/statistics/daily`
- **설명:** 특정 날짜의 건강 통계 조회
- **Query Parameters:**
  - `date` (optional, string): 통계를 조회할 날짜 (ISO 포맷: "YYYY-MM-DD" 또는 "YYYY-MM-DDTHH:MM:SS", 기본값: 오늘)
- **응답:**
```json
{
  "success": true,
  "data": {
    "date": "2024-01-15",
    "calories": 1800,
    "macros": {
      "calories": 1800,
      "protein": 120,
      "carbs": 200,
      "fat": 60,
      "vitamin_c": 50,
      "vitamin_d": 10,
      "zinc": 8
    },
    "mealCount": 3,
    "mealHistory": [
      {
        "id": "meal-uuid-1",
        "consumedAt": "2024-01-15T08:00:00",
        "mealType": "breakfast",
        "notes": "맛있었음",
        "recipeId": "recipe-uuid-1"
      },
      {
        "id": "meal-uuid-2",
        "consumedAt": "2024-01-15T12:30:00",
        "mealType": "lunch",
        "notes": null,
        "recipeId": "recipe-uuid-2"
      },
      {
        "id": "meal-uuid-3",
        "consumedAt": "2024-01-15T19:00:00",
        "mealType": "dinner",
        "notes": "저녁 식사",
        "recipeId": "recipe-uuid-3"
      }
    ]
  }
}
```
- **응답 필드 설명:**
  - `date` (string): 조회한 날짜 (YYYY-MM-DD 형식)
  - `calories` (number): 해당 날짜의 총 칼로리 (macros.calories와 동일)
  - `macros` (object): 영양소 정보
    - `calories` (number): 총 칼로리 (kcal)
    - `protein` (number): 단백질 (g)
    - `carbs` (number): 탄수화물 (g)
    - `fat` (number): 지방 (g)
    - `vitamin_c` (number): 비타민C (mg)
    - `vitamin_d` (number): 비타민D (μg)
    - `zinc` (number): 아연 (mg)
  - `mealCount` (number): 해당 날짜의 식사 횟수
  - `mealHistory` (array): 식사 기록 목록
    - `id` (string): 식사 ID
    - `consumedAt` (string): 섭취 시간 (ISO 8601 형식)
    - `mealType` (string | null): 식사 타입 (breakfast, lunch, dinner, snack)
    - `notes` (string | null): 메모
    - `recipeId` (string | null): 레시피 ID
- **특징:** 
  - 칼로리, 영양소 섭취량 등 일일 통계
  - **meal 테이블 기준으로만 계산** (Meal과 Recipe LEFT JOIN)
  - recipeId가 NULL인 meal은 영양소 계산에서 제외됨
  - userId로 자동 필터링 (본인 데이터만 조회)
  - date 파라미터가 없으면 오늘 날짜 기준으로 조회

## 공통 사항

### 인증
- 대부분의 API는 Bearer Token 인증 필요
- `Authorization: Bearer {token}` 헤더로 전달
- 토큰은 `/auth/login` 또는 `/auth/register`에서 받을 수 있음

### 에러 응답
- **400:** 잘못된 요청 (Bad Request)
- **401:** 인증 실패 (Unauthorized)
- **403:** 권한 없음 (Forbidden)
- **404:** 리소스 없음 (Not Found)

### 공통 응답 형식
- 대부분의 API는 `success`, `data`, `message` 필드를 포함한 일관된 응답 형식 사용
- 리스트 응답: `{data: [...]}`
- 단일 항목 응답: `{data: {...}}`
- 삭제/업데이트 응답: `{success: true, message: "..."}`

### 보안
- 모든 사용자 데이터는 userId로 자동 필터링
- 본인 데이터만 조회/수정/삭제 가능
- 다른 사용자의 데이터 접근 시 403 또는 404 에러 반환
